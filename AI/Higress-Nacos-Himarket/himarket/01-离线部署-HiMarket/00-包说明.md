# 00 · 离线部署 HiMarket（实操包）

> **本目录是一个完整实操包**：主手册 + 备料清单 + 可执行脚本 + K8s 清单，放在一处，不用跨目录找。
> 命名规则：`0N-` 文档｜`1N-` 可执行脚本｜`2N-` YAML 清单｜`00-` 本说明。

## 这个包做什么

在内网 / 离线环境把 HiMarket v0.8.2 完整装起来（Harbor 私有镜像 + 自有 LB），已验收可复现。

## 一对一配对表

| 角色 | 文件 | 用途 | 用在哪一步 |
|---|---|---|---|
| 主手册 | `02-部署主手册-可复现版.md` | 逐命令还原部署，含 28 个坑的现场解法、预期输出、验收清单、升级回滚 | **全程照它走** |
| 备料 | `01-物料清单.md` | 版本矩阵、11 个镜像、资源占用、端口清单、附录 A/B 前置条件 | 第 0 步 |
| 参考 | `03-在线部署参考.md` | 能访问公网 registry 时的标准 Helm 路径，讲清 `install.sh` 内部机制与三套版本号 | 仅参考，离线别照做 |
| 脚本 | `11-fetch-offline-bundle.sh` | 摆渡机（有外网）打包源码 + helm + chart + 镜像 tar + SHA256 | 备料后第 1 步 |
| 脚本 | `12-mirror-himarket-images.sh` | 只搬镜像，用于增量升级；`helm template` 渲染抓全部 image 引用 | 增量场景 |
| 脚本 | `13-import-to-harbor.sh` | 内网侧 `docker load` → 替换 registry host → retag → push Harbor | 摆渡后 |
| 脚本 | `14-prepare-internal.sh` | 校验离线文件、装 helm、改 `install.sh` 里写死的公网 registry 与 tag | 导入后 |
| 脚本 | `15-preflight-check.sh` | 部署前 12 项自检，**只读不改集群**，输出 PASS/FAIL 表 | 执行安装前 |
| 清单 | `21-local-storage-pv.yaml` | 静态 PV。集群只有 `local-storage`（no-provisioner），不预建则 PVC 永久 Pending | 安装前 apply |
| 清单 | `22-nacos-ingress.yaml` | Nacos 控制台经 Higress + CLB 对外暴露 | 安装后 |

## 执行顺序

```
01-物料清单.md → 11-fetch-offline-bundle.sh → 摆渡到内网 → 13-import-to-harbor.sh
→ 14-prepare-internal.sh → 15-preflight-check.sh（12 项全 PASS）
→ kubectl apply -f 21-local-storage-pv.yaml → 22-nacos-ingress.yaml
→ 照 02-部署主手册-可复现版.md 走 install.sh
```

## 验收 / 一句话记忆

`15-preflight-check.sh` 全 PASS；`kubectl -n himarket get pods` 全 Running；门户与后台能打开。
**镜像变量只能改 `install.sh`**（改 values/env 都无效）；SA 要逐个 patch 再删 Pod；PVC 要手工建 PV。
