# HiMarket 离线部署手册（可复现版）

> 本文是 2026-10-27 实际部署过程的完整还原，按顺序执行即可从零复现。
> 每一步后标注了 `⚠️ 坑` 的，是本项目实际踩过的问题，详细前因后果见配套文档《03-部署问题排查记录.md》。
>
> **环境基线**
> - 集群：移动云 KCS，K8s `v1.29.5-eki.4.1.0`，containerd 1.6.28
> - 节点：3 master + 3 worker
>   - master：`<HIMARKET_NODE_MASTER>` / `-m-7kff7` / `-m-rsxqg`
>   - worker：`<HIMARKET_NODE_WORKER1>` / `-s-826fc` / `-s-kzf7p`
> - 私有仓库：`http://harbor.example.internal`，project `ai-platform`
> - 负载均衡：共享型 CLB `elb_ai_platform_dev`，内网 VIP `<MODEL_GW_IP>`
> - 网络：完全离线，无公网出口

## 0. 版本与架构决策（先定，后面全部依赖这些）

### 0.1 版本矩阵

| 物料 | 版本 |
|---|---|
| HiMarket 应用 | v0.8.2 |
| himarket chart | 0.1.0（随源码包） |
| nacos chart | 0.1.0（随源码包） |
| Nacos 镜像 | v3.2.1-2026.03.30 |
| higress chart | 2.2.5 |
| Redis Stack 镜像 | 7.4.0-v3 |
| MySQL 镜像 | tag `latest`，实际版本 8.0.32 |
| Helm（集群侧） | v3.15.3 |

### 0.2 架构决策

```
用户 → CLB <MODEL_GW_IP>:30080/30443
        → higress-gateway (LoadBalancer, 3 副本)
            → Ingress (Host 分流, ingressClass=himarket)
                ├─ himarket-admin.example.internal → himarket-admin    (ClusterIP)
                └─ himarket.example.internal       → himarket-frontend (ClusterIP)
```

**关键决策：只有 `higress-gateway` 一个 Service 是 LoadBalancer，其余全部 ClusterIP。**

原因：集群策略不允许 NodePort；共享 CLB 端口资源紧张；业务统一走网关路由。

> `⚠️ 坑-01`：这个决策会导致官方初始化钩子全部失败，处理方式见第 7 章。上游默认会创建 4 个 LB（admin / frontend / nacos / console），钩子正是依赖这几个 LB 的 IP。

| 文件 | 用途 |

```bash
mkdir -p /root/offline && cd /root/offline
```

> `⚠️ 坑-03`：higress 的发布包是否包含两个子 chart，必须解包后检查 `charts/higress/charts/` 目录。

```bash
mkdir -p /opt/charts && tar xzf charts/higress-2.2.5.tgz -C /opt/charts
```

### 1.3 推送到私有 Harbor

镜像统一按「保留原路径、只换 registry host」的规则重命名：

```
opensource-registry.../higress-group/himarket-server:v0.8.2
  → harbor.example.internal/ai-platform/himarket/himarket-server:v0.8.2
nacos-registry.../nacos/nacos-server:vX
  → harbor.example.internal/ai-platform/nacos/nacos-server:vX
higress-registry.../higress/gateway:X
  → harbor.example.internal/ai-platform/higress/gateway:X
```

最终 Harbor 里是 **11 个镜像、12 个 tag**（mysql 同时保留 `latest` 和 `8.0.32`）：

| 仓库 | Tag |
|---|---|
| `ai-platform/himarket/himarket-server` | v0.8.2 |
| `ai-platform/himarket/himarket-admin` | v0.8.2 |
| `ai-platform/himarket/himarket-frontend` | v0.8.2 |
| `ai-platform/himarket/sandbox` | v0.8.2 |
| `ai-platform/himarket/mysql` | latest、8.0.32 |
| `ai-platform/nacos/nacos-server` | v3.2.1-2026.03.30 |
| `ai-platform/higress/console` | 2.2.5 |
| `ai-platform/higress/gateway` | 2.2.5 |
| `ai-platform/higress/higress` | 2.2.5 |
| `ai-platform/higress/pilot` | 2.2.5 |
| `ai-platform/higress/redis-stack-server` | 7.4.0-v3 |

> `⚠️ 坑-06`：Harbor 是 **HTTP 80**，docker 必须配 `insecure-registries`。
> `⚠️ 坑-07`：docker daemon 的 `proxies.no-proxy` 必须包含 Harbor 域名，否则内网请求被公司代理转发返回 **503**，表现为 `docker login: 503 Service Unavailable`。

推送前先登录（凭据需对 `ai-platform` 项目有 push 权限）：

```bash
docker login http://harbor.example.internal -u ai-platform --password-stdin <<< '<HARBOR_PASSWORD>'
```

推送后做一次独立核对（Harbor API 的 repository 名需要**双重 URL 编码**，否则会误判为不存在）：

```bash
enc=$(python3 -c "import urllib.parse,sys;print(urllib.parse.quote(urllib.parse.quote(sys.argv[1],safe=''),safe=''))" "himarket/himarket-server")
curl -s -u "<user>:<pass>" \
  "http://harbor.example.internal/api/v2.0/projects/ai-platform/repositories/$enc/artifacts?page_size=50" \
  | python3 -c "import sys,json;d=json.load(sys.stdin);print([t['name'] for a in d if a.get('tags') for t in a['tags']])"
# 期望：['v0.8.2']
```

## 2. 集群侧准备

### 2.1 创建 namespace 与规格确认

```bash
kubectl create namespace himarket
```

顺手确认 worker 的可分配资源，它决定后面 `HIMARKET_SIZE` 取值（small=1C2G / standard=2C4G / large=4C8G）：

```bash
kubectl get nodes -l '!node-role.kubernetes.io/control-plane' \
  -o custom-columns='NAME:.metadata.name,CPU:.status.allocatable.cpu,MEM:.status.allocatable.memory'
```

> 本项目 3 台 worker 用 `standard`（各组件 2C4G）。**不要选 `small`** —— 会把 Higress 网关副本强制压成 1。
> 所有组件（含 Higress）都装在这个 namespace 里，不会再创建 `higress-system`。

### 2.2 创建 Harbor 拉取凭据

```bash
kubectl create secret docker-registry harbor-secret \
  --docker-server=harbor.example.internal \
  --docker-username=ai-platform \
  --docker-password='<HARBOR_PASSWORD>' \
  -n himarket
```

验证类型必须是 `kubernetes.io/dockerconfigjson`：

```bash
kubectl get secret harbor-secret -n himarket -o jsonpath='{.type}{"\n"}'
```

> `⚠️ 坑-08`：secret 建好 ≠ Pod 能拉。**必须挂到 ServiceAccount 上**，而且这个 chart 用的是独立 SA（`himarket` / `higress-gateway` / `higress-console` / `higress-controller`），只改 `default` 没用。见 2.4。

### 2.3 验证节点能拉 Harbor

```bash
kubectl run pulltest -n himarket --rm -it --restart=Never \
  --image=harbor.example.internal/ai-platform/himarket/himarket-server:v0.8.2 \
  --overrides='{"spec":{"imagePullSecrets":[{"name":"harbor-secret"}]}}' \
  -- true
```

> 这里显式在 spec 里注入 secret，**不能**代表 chart 的独立 SA 能用。这一步只验证网络连通性和认证正确性。
> 出现 `ErrImagePull` 且原因是 `http: server gave HTTP response to HTTPS client`，说明节点 containerd 不认 HTTP registry，需在云平台配置 insecure registry。

### 2.4 给 ServiceAccount 挂 secret（**分两个阶段，顺序很重要**）

**阶段一：部署前（只能处理 `default`）**

此时 chart 还没安装，`himarket` / `higress-*` 这些 SA 根本不存在，patch 会报 NotFound：

```bash
kubectl patch sa default -n himarket --type merge \
  -p '{"imagePullSecrets":[{"name":"harbor-secret"}]}' 2>/dev/null || true
```

> `sandbox-shared` 用的就是 `default` SA，所以这一步能让它正常拉镜像。

**阶段二：`helm install` 创建出 SA 之后（关键，别漏）**

`install.sh` 装完 himarket chart 后立即执行，或手动部署后立刻补：

```bash
for sa in himarket higress-gateway higress-console higress-controller; do
  kubectl patch sa "$sa" -n himarket --type merge \
    -p '{"imagePullSecrets":[{"name":"harbor-secret"}]}' 2>/dev/null
done

kubectl get sa -n himarket -o jsonpath='{range .items[*]}{.metadata.name}{" -> "}{.imagePullSecrets}{"\n"}{end}'
```

然后删 Pod 让其带新 SA 重建：

```bash
kubectl delete pod -n himarket --all
```

**已知的 SA 归属关系（本项目实测）**

| Pod | ServiceAccount |
|---|---|
| himarket-server / admin / frontend / mysql | `himarket` |
| sandbox-shared | `default` |
| higress-gateway | `higress-gateway` |
| higress-console | `higress-console` |
| higress-controller | `higress-controller` |

> `⚠️ 坑-08`：chart 用的是独立 SA，**只改 `default` 不够**，`himarket-*` 四个 Pod 会全部 `ImagePullBackOff`。
> `⚠️ 坑-09`：helm 回滚/卸载会**连带删除 chart 创建的 SA**，重装后必须重新执行阶段二。
> `⚠️ 坑-10`：`imagePullSecrets` 在 Pod 创建时固化，patch SA 后**必须删 Pod 重建**才生效。

### 2.5 存储：创建静态 PV

先确认 StorageClass：

```bash
kubectl get sc
```

本项目实际只有：

```
NAME            PROVISIONER                    VOLUMEBINDINGMODE
local-storage   kubernetes.io/no-provisioner   WaitForFirstConsumer
```

> `⚠️ 坑-11`：`no-provisioner` **不会动态创建 PV**。chart 需要 2 个 50Gi PVC，不手工建 PV 会永久 `Pending`，mysql 起不来，`install.sh` 300 秒后整体回滚。

创建两个 PV（用 hostPath + DirectoryOrCreate，不需要 SSH 到节点）：

```yaml
# pv.yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: himarket-mysql-pv
  labels: { app: himarket, pv-for: mysql }
spec:
  capacity: { storage: 50Gi }
  accessModes: [ReadWriteOnce]
  volumeMode: Filesystem
  persistentVolumeReclaimPolicy: Retain
  storageClassName: local-storage
  hostPath:
    path: /var/lib/paascontainer/himarket/mysql
    type: DirectoryOrCreate
  nodeAffinity:
    required:
      nodeSelectorTerms:
        - matchExpressions:
            - key: kubernetes.io/hostname
              operator: In
              values: [<HIMARKET_NODE_WORKER2>]
---
apiVersion: v1
kind: PersistentVolume
metadata:
  name: himarket-sandbox-pv
  labels: { app: himarket, pv-for: sandbox }
spec:
  capacity: { storage: 50Gi }
  accessModes: [ReadWriteOnce]
  volumeMode: Filesystem
  persistentVolumeReclaimPolicy: Retain
  storageClassName: local-storage
  hostPath:
    path: /var/lib/paascontainer/himarket/sandbox
    type: DirectoryOrCreate
  nodeAffinity:
    required:
      nodeSelectorTerms:
        - matchExpressions:
            - key: kubernetes.io/hostname
              operator: In
              values: [<HIMARKET_NODE_WORKER2>]
```

```bash
kubectl apply -f pv.yaml
kubectl get pv     # 两个都要 Available
```

校验 nodeAffinity 指向的是 **worker**：

```bash
kubectl get pv -o jsonpath='{range .items[*]}{.metadata.name}{" -> "}{.spec.nodeAffinity.required.nodeSelectorTerms[0].matchExpressions[0].values[0]}{"\n"}{end}'
```

> `⚠️ 坑-12`：如果填成 master 节点，因控制面有 `NoSchedule` 污点，mysql 永远调度不上去。

> `⚠️ 坑-13`：两个 PV 规格完全相同（50Gi/RWO/同一 SC），PVC 绑定会**交叉**：
> `mysql-data-mysql-0` → `himarket-sandbox-pv`，`sandbox-workspace-pvc` → `himarket-mysql-pv`。
> 即 **MySQL 真实数据落在 `/var/lib/paascontainer/himarket/sandbox` 目录**。功能无影响，但备份/排障必须按实际绑定关系来。

## 4. 配置改造（**全流程最关键的一章**）

原因：`install.sh` 第 611 行会 `unset` 所有镜像相关变量，第 818 行把默认值写死为公网 registry，第 1296 行再用 `--set` 强制覆盖 chart。**所以只改 `values.yaml` 是无效的，必须改脚本里的默认值。**

> `⚠️ 坑-15`：镜像相关变量（`HIMARKET_HUB` / `HIMARKET_IMAGE_TAG` / `NACOS_IMAGE_REGISTRY` / `NACOS_IMAGE_REPOSITORY` / `NACOS_VERSION` / `HIGRESS_CHART_REF` 等）写在 `~/himarket-install.env` 里会被 `unset` 掉，同样无效。

### 4.1 备份

```bash
cd /var/lib/paascontainer/himarket/himarket-0.8.2/deploy/helm
cp install.sh install.sh.orig
cd /var/lib/paascontainer/himarket
cp charts/higress/charts/higress-core/values.yaml    charts/higress/charts/higress-core/values.yaml.orig
cp charts/higress/charts/higress-console/values.yaml charts/higress/charts/higress-console/values.yaml.orig
cp himarket-0.8.2/deploy/helm/himarket/values.yaml   himarket-0.8.2/deploy/helm/himarket/values.yaml.orig
```

### 4.2 改 install.sh 的镜像默认值

```bash
cd /var/lib/paascontainer/himarket/himarket-0.8.2/deploy/helm

sed -i 's#HIMARKET_HUB:-opensource-registry.cn-hangzhou.cr.aliyuncs.com/higress-group#HIMARKET_HUB:-harbor.example.internal/ai-platform/himarket#' install.sh
sed -i 's#NACOS_IMAGE_REGISTRY:-nacos-registry.cn-hangzhou.cr.aliyuncs.com#NACOS_IMAGE_REGISTRY:-harbor.example.internal#' install.sh
sed -i 's#NACOS_IMAGE_REPOSITORY:-nacos/nacos-server#NACOS_IMAGE_REPOSITORY:-ai-platform/nacos/nacos-server#' install.sh

# 交互提示里的默认值也要改（两处块）
sed -i 's#prompt HIMARKET_HUB "HiMarket image hub" "opensource-registry.cn-hangzhou.cr.aliyuncs.com/higress-group"#prompt HIMARKET_HUB "HiMarket image hub" "harbor.example.internal/ai-platform/himarket"#' install.sh
sed -i 's#prompt HIMARKET_IMAGE_TAG "HiMarket image tag" "latest"#prompt HIMARKET_IMAGE_TAG "HiMarket image tag" "v0.8.2"#' install.sh
sed -i 's#prompt HIMARKET_MYSQL_IMAGE_TAG "MySQL image tag" "latest"#prompt HIMARKET_MYSQL_IMAGE_TAG "MySQL image tag" "8.0.32"#' install.sh
sed -i 's#prompt NACOS_IMAGE_REGISTRY "Nacos image registry" "nacos-registry.cn-hangzhou.cr.aliyuncs.com"#prompt NACOS_IMAGE_REGISTRY "Nacos image registry" "harbor.example.internal"#' install.sh
sed -i 's#prompt NACOS_IMAGE_REPOSITORY "Nacos image repository" "nacos/nacos-server"#prompt NACOS_IMAGE_REPOSITORY "Nacos image repository" "ai-platform/nacos/nacos-server"#' install.sh
```

补充非交互模式的兜底默认值（在 `NACOS_IMAGE_REPOSITORY` 那一行后插入 3 行）：

```python
python3 - <<'PY'
p='install.sh'
s=open(p).read()
anchor='NACOS_IMAGE_REPOSITORY="${NACOS_IMAGE_REPOSITORY:-ai-platform/nacos/nacos-server}"'
add=('\n        HIMARKET_IMAGE_TAG="${HIMARKET_IMAGE_TAG:-v0.8.2}"'
     '\n        HIMARKET_MYSQL_IMAGE_TAG="${HIMARKET_MYSQL_IMAGE_TAG:-8.0.32}"'
     '\n        NACOS_VERSION="${NACOS_VERSION:-v3.2.1-2026.03.30}"')
if 'HIMARKET_IMAGE_TAG="${HIMARKET_IMAGE_TAG:-v0.8.2}"' not in s:
    s = s.replace(anchor, anchor + add, 1)
open(p,'w').write(s)
PY
```

### 4.3 禁用联网的 helm repo 操作

```bash
sed -i 's|^\(\s*\)helm repo add|\1: # [offline] helm repo add|' install.sh
sed -i 's|^\(\s*\)helm repo update|\1: # [offline] helm repo update|' install.sh
```

> `⚠️ 坑-16`：**不能只加 `#` 注释**。`add_repos()` 函数体如果只剩注释，bash 会报 `syntax error near unexpected token '}'`。必须保留一条 `:` 作为 no-op 命令。

### 4.4 改 Higress chart 指向本地与内网仓库

```bash
cd /var/lib/paascontainer/himarket

# core 的 hub（gateway/pilot/higress/redis 都走它）
sed -i 's#higress-registry\.cn-hangzhou\.cr\.aliyuncs\.com#harbor.example.internal/ai-platform#g' \
  charts/higress/charts/higress-core/values.yaml

# console 的 hub（不受 global.hub 控制，必须单独改）
sed -i 's#higress-registry\.cn-hangzhou\.cr\.aliyuncs\.com#harbor.example.internal/ai-platform#g' \
  charts/higress/charts/higress-console/values.yaml
```

> `⚠️ 坑-17`：`higress-console` 有自己的 hub 字段，只改 `higress-core.global.hub` 时 console 镜像仍指向公网。

改 `install.sh` 里的 Higress chart 引用（在 unset 名单里，所以必须改默认值）：

```bash
cd himarket-0.8.2/deploy/helm
sed -i 's#HIGRESS_REPO_NAME="${HIGRESS_REPO_NAME:-higress.io}"#HIGRESS_REPO_NAME="${HIGRESS_REPO_NAME:-local}"#' install.sh
sed -i 's#HIGRESS_REPO_URL="${HIGRESS_REPO_URL:-https://higress.cn/helm-charts}"#HIGRESS_REPO_URL="${HIGRESS_REPO_URL:-file:///var/lib/paascontainer/himarket/charts}"#' install.sh
sed -i 's#HIGRESS_CHART_REF="${HIGRESS_CHART_REF:-higress.io/higress}"#HIGRESS_CHART_REF="${HIGRESS_CHART_REF:-/var/lib/paascontainer/himarket/charts/higress}"#' install.sh
```

### 4.5 修 sandbox 镜像 tag

```bash
  --set higress-core.global.ingressClass=himarket \
  --set higress-console.global.ingressClass=himarket \
  --set higress-console.service.type=ClusterIP \
  --set higress-console.admin.username=admin \
  --set "higress-console.admin.password=${HIGRESS_PWD}" \
  --set higress-core.gateway.replicas=3
```

> `⚠️ 坑-22`：`helm install/upgrade` 被中断后会留下 `pending-install` 锁，再执行任何 helm 操作都报 `another operation (install/upgrade/rollback) is in progress`。必须先 `helm uninstall`（或删 `sh.helm.release.v1.higress.v1` secret）清掉。

## 7. 初始化钩子（本项目最曲折的一步）

### 7.1 为什么会失败

`install.sh` 的 `run_hooks` 是**在操作机本地用 bash 执行** `hooks/post_ready.d/*.sh`，不是跑在 Pod 里。每个钩子的取址逻辑是：

```bash
NACOS_HOST=$(kubectl get svc nacos -n himarket \
  -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
if [[ -z "$NACOS_HOST" ]]; then
  NACOS_HOST="nacos.himarket.svc.cluster.local"    # 回退集群内部域名
fi
```

> `⚠️ 坑-25`：ClusterIP 类型 Service 没有 `status.loadBalancer` 字段 → 取到空 → 回退到 `*.svc.cluster.local`。这个域名只对 Pod 有效（CoreDNS 提供），**节点上解析不了** → curl 退出码 6 → 日志显示 `HTTP 000`。

涉及的两个钩子：`10-init-nacos-admin.sh`（nacos）、`20-init-himarket-admin.sh`（admin）、`60-init-portal-developer.sh`（frontend + admin）。`65-sync-nacos-market.sh` 支持 `HIMARKET_API_URL` 覆盖。

### 7.2 解法：hosts + port-forward 伪造集群内 DNS 视图

```bash
cat >> /etc/hosts <<'EOF'
127.0.0.2 himarket-admin.himarket.svc.cluster.local
127.0.0.3 himarket-frontend.himarket.svc.cluster.local
127.0.0.4 nacos.himarket.svc.cluster.local
EOF

kubectl -n himarket port-forward --address 127.0.0.2 svc/himarket-admin    80:80   >/tmp/pf-admin.log 2>&1 &
kubectl -n himarket port-forward --address 127.0.0.3 svc/himarket-frontend 80:80   >/tmp/pf-front.log 2>&1 &
kubectl -n himarket port-forward --address 127.0.0.4 svc/nacos            8080:8080 >/tmp/pf-nacos.log 2>&1 &
sleep 3

curl -s -o /dev/null -w 'admin    : %{http_code}\n' http://himarket-admin.himarket.svc.cluster.local/
curl -s -o /dev/null -w 'frontend : %{http_code}\n' http://himarket-frontend.himarket.svc.cluster.local/
curl -s -o /dev/null -w 'nacos    : %{http_code}\n' http://nacos.himarket.svc.cluster.local:8080/nacos/
```

三个都不能是 `000`（nacos 返回 500 也算通）。

### 7.3 执行钩子

```bash

```

期望结果：

```

钩子成功: 65-sync-nacos-market.sh
钩子失败: 60-init-portal-developer.sh     ← 见坑-26
```

## 10. 日常运维约定（**必须遵守**）

1. **禁止全量执行 `./install.sh`** —— 带 `--wait --atomic`，在网关 Service 长期 pending 的情况下必然超时回滚。升级用第 5.4 节那条不带 `--wait` 的 `helm upgrade`。
2. **重装后必须重新 patch ServiceAccount** —— helm 回滚会删除 chart 创建的 SA，不补就 `ImagePullBackOff`（第 2.4 节）。
3. **节点扩缩容要手工维护 CLB 后端池** —— 监听器是手建的，CCM 不托管。
4. **执行 helm 前先查锁** —— `helm list -n himarket --all`，有 `pending-*` 先 `helm uninstall`。
5. **备份注意目录交叉** —— MySQL 真实数据在 `/var/lib/paascontainer/himarket/sandbox`，沙箱在 `.../mysql`。
6. **`~/himarket-install.env` 含全部密码** —— 单独加密备份，不要留在集群节点上。

## 11. 版本升级与回滚

### 11.1 升级 HiMarket 应用版本（例如 v0.8.2 → 后续版本）

1. 摆渡机按 1.1 / 1.2 准备新版本的源码包与镜像，推到 Harbor（保留路径、改 tag）
2. 集群侧解包新源码包
3. **重新执行第 4 章的全部改造**（新源码包里的 `install.sh` 和 values 都是原始状态，之前的修改不会带过来）
4. 只升级 himarket release，不动 higress：

```bash
cd /var/lib/paascontainer/himarket/himarket-<新版本>/deploy/helm
# 复用原 env 里的密码，避免数据库连接失败
helm upgrade himarket ./himarket -n himarket --reuse-values \
  --set hub=harbor.example.internal/ai-platform/himarket \
  --set frontend.image.tag=v<新版本> \
  --set admin.image.tag=v<新版本> \
  --set server.image.tag=v<新版本> \
  --set mysql.image.tag=8.0.32
```

> 注意：`sandbox.image.tag` 不在 `--set` 里，要去 `values.yaml` 改（同坑-18）。

### 11.2 回滚

```bash
helm history himarket -n himarket          # 看 revision
helm rollback himarket <上一版revision> -n himarket
```

回滚后必须：

```bash
kubectl delete pod -n himarket --all       # 让 Pod 用回旧镜像
kubectl get pvc -n himarket                # 确认 PVC 仍 Bound
```

> 数据库迁移是单向的：如果新版本跑过 Flyway 迁移，回滚应用不会自动回滚表结构。跨大版本回滚前必须备份 MySQL。
> v0.8.1 → v0.8.2 官方说明无需迁移；v0.7.x → v0.8.x 有 `V21`/`V22` 迁移。

### 11.3 备份（当前无自动化，需手工）

```bash
kubectl exec -n himarket mysql-0 -- sh -c \
  'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --all-databases --single-transaction' \
  > /root/himarket-backup-$(date +%F).sql
```

> 注意备份的是数据库逻辑内容，与 hostPath 目录（`/var/lib/paascontainer/himarket/sandbox`，见坑-13）无关。
