## 2. 需要下载的文件（4 类，共 4 个直接下载项 + 一批镜像）

### 2.1 安装包（2 个）

| 文件 | 版本 | 下载地址 |
|---|---|---|
| `v0.8.2.tar.gz` → `himarket-0.8.2.tar.gz` | v0.8.2 | `https://github.com/higress-group/himarket/archive/refs/tags/v0.8.2.tar.gz` |
| `helm-v3.22.1-linux-amd64.tar.gz` | v3.22.1 | `https://get.helm.sh/helm-v3.22.1-linux-amd64.tar.gz` |

> HiMarket **不发布独立的 chart tgz**，himarket 和 nacos 两个 chart 都在这份源码包里，所以源码包是必须项，不是可选项。
> 要部署前一版就把 URL 里的 `v0.8.2` 换成 `v0.8.1`。

### 2.2 Chart 包（3 个 + 2 个子 chart）

| Chart | 版本 | 获取方式 |
|---|---|---|
| `himarket` | 0.1.0 | 源码包自带，无需单独下载 |
| `nacos` | 0.1.0 | 源码包自带，无需单独下载 |
| `higress` | 2.2.5 | **必须单独 `helm pull`** |
| `higress-core` | 2.2.5 | higress 的子 chart，`file://` 依赖 |
| `higress-console` | 2.2.5 | higress 的子 chart，**远程仓库依赖** |

```bash
helm repo add higress.io https://higress.io/helm-charts/
helm repo update
helm pull higress --repo https://higress.io/helm-charts/ --version 2.2.5 --untar --untardir ./charts
```

**拉完立刻检查依赖是否打进去了（关键一步）：**

```bash
ls -1 charts/higress/charts/
# 期望看到：
#   higress-core-2.2.5.tgz
#   higress-console-2.2.5.tgz
```

如果 `charts/` 是空的或缺 `higress-console`，说明发布的 tgz 没把依赖打进来，此时 `helm pull` 不够，需要补：

```bash
# 补 console 子 chart
helm pull higress-console --repo https://higress.io/helm-charts/ --version 2.2.5 \
  --untar --untardir ./charts/higress/charts

# higress-core 是 file:// 依赖，只能从源码拿，下载 higress 源码包兜底
curl -fLO https://github.com/higress-group/higress/archive/refs/tags/v2.2.5.tar.gz
tar xzf v2.2.5.tar.gz          # 得到 higress-2.2.5/helm/core
```

> 这一步不验证就搬进内网，装到第 9 步会报 `found in Chart.yaml, but missing in charts/ directory: higress-console`，而且离线环境无解。

## 3. 存储与资源（全内置时的实际占用）

| 资源 | 数量 | 说明 |
|---|---|---|
| PVC（mysql） | 1 × 50Gi RWO | 需 StorageClass |
| PVC（sandbox） | 1 × 50Gi RWO | 需 StorageClass |
| PVC（redis） | 0 | `persistence.enabled` 默认 false，开启则 1Gi |
| **磁盘合计** | **约 100Gi+** | 云盘按需确认配额 |

| 维度 | requests 合计 | limits 合计 |
|---|---|---|
| 计算 | 约 **11C / 20G** | 约 **20C / 34G** |

分布：himarket 三件套各 2C4G、sandbox 1C1G(lim 4C8G)、mysql 1C1G(lim 2C2G)、nacos 0.5C1G(lim 2C4G)、higress-gateway 默认 2 副本、console/controller 各 ~0.5C1G。

> 3 台 worker 若为 4C8G（总 12C24G），requests 刚好贴线，任一节点打满就调度失败 → 建议 `size: small` 或把 worker 提到 8C16G。

### 6.3 StorageClass 结论：必须手工建 PV

```
NAME            PROVISIONER                    RECLAIMPOLICY  VOLUMEBINDINGMODE      ALLOWVOLUMEEXPANSION
local-storage   kubernetes.io/no-provisioner   Delete         WaitForFirstConsumer   false
```

`no-provisioner` = **不会动态创建 PV**。HiMarket chart 会申请 2 个 50Gi PVC（mysql、sandbox），没有 PV 可绑 → PVC 永远 Pending → mysql 起不来 → `install.sh` 在 300s 超时后 `--atomic` 整体回滚。

**解法**：部署前先创建 2 个静态 PV，清单见 `01-离线部署-HiMarket/21-local-storage-pv.yaml`：

```bash
# 1. 选一台 worker 填进 nodeAffinity
kubectl get nodes -l '!node-role.kubernetes.io/control-plane'

# 2. 改 01-离线部署-HiMarket/21-local-storage-pv.yaml 里的 NODE 名，然后
kubectl apply -f 01-离线部署-HiMarket/21-local-storage-pv.yaml
kubectl get pv          # 应为 Available

# 3. 再装 HiMarket，PVC 会自动绑定（WaitForFirstConsumer 由调度器触发）
```

PV 用 `hostPath + DirectoryOrCreate`，kubelet 自动建目录，**不需要 SSH 到 worker**；`reclaimPolicy: Retain` 防误删。代价是 mysql 绑死在单节点，节点故障即不可用——研发/PoC 可接受，生产建议改用云盘 CSI。

> 备选方案：装 `local-path-provisioner` 实现动态供给，但要额外搬 2 个镜像（provisioner + helper），并且仍然绑节点。静态 PV 更省事。

## 7. 一句话执行顺序

```bash
# 外网摆渡机：下载 → 拉 chart → 查依赖 → 渲染取镜像 → pull → save → 打包
bash 11-fetch-offline-bundle.sh          # 已提供，一次跑完 2.1~2.5

# 内网：解包 → 装 helm → load/retag/push → 改 install.sh 默认值 → install
bash 13-import-to-harbor.sh images.txt
```

> 注意是「改 `install.sh` 默认值」，不是「改 values.yaml」。脚本会 `unset` 镜像变量并用 `--set` 覆盖，
> 只改 values 不生效，详见《02-部署主手册-可复现版.md》第 4 章。

## 8. 附录 A：集群外软件清单（操作机 / 集群必须先就绪）

只有「集群内工作负载」和「镜像」会被 Helm 装进去，下面这些是前置条件，缺一个都会在部署中途失败。

| 软件 | 版本要求 | 用途 | 本项目实测 |
|---|---|---|---|
| Kubernetes | ≥ 1.20 | 运行平台 | 1.29.5 ✓ |
| containerd | 1.6+ | 容器运行时（无需 docker） | 1.6.28 ✓ |
| **Helm** | **3.x（≥ 3.10）** | 部署引擎，`install.sh` 强依赖 | 集群自带 v3.15.3 ✓ |
| kubectl | 与集群同版本 | 集群操作 | ✓ |
| **bash** | **4.0+** | `install.sh` 用了关联数组 `declare -A` | ✓ |
| curl | 任意 | 脚本探测 registry | ✓ |
| jq | 1.6+ | 脚本解析 JSON | 需确认，最小化镜像常缺 |
| python3 | 3.8+ | `install.sh` 处理 JSON | CentOS 7 系默认没有 |
| openssl | 1.1+ | 生成随机密码 | ✓ |
| Harbor | 2.x | 私有镜像仓库 | `http://harbor.example.internal` ✓ |
| StorageClass | 云盘/网络盘 CSI | mysql 与 sandbox 的 PVC | 仅 `local-storage`，需手工建 PV |
| 外部 LB + 域名 | — | 入口暴露 | 共享 CLB `<MODEL_GW_IP>` ✓ |

> **不需要**：JDK 17、Node.js 18、Maven（源码构建才要）；**不需要**：节点装 docker（KCS 用 containerd，验证用 `crictl`）。
