# 00 · MCP 生产化方案（实操包 · 设计完成，未落地）

> `0N-` 文档｜`1N-` 可执行脚本｜`2N-` YAML 清单｜`00-` 本说明。
> `Dockerfile` 是唯一不加序号的文件 —— `docker build` 靠约定名识别，改名会破坏构建。

## 这个包做什么

把 `03-接入MCP-PoC/` 的 PoC 形态改造成可运维的生产形态：自建镜像、独立命名空间、
Nacos 自动注册、网关自动暴露、鉴权限流与灰度。**本包的脚本、Dockerfile 与两份 YAML 清单均为设计态，未在任何环境执行过**；
两份文档是决策依据，不是执行记录。

## 落地前置条件（四个都缺一不可）

1. 能往 Harbor 推自建镜像；2. Nacos 有建 AI 命名空间的权限；
3. 有可用的生产 MCP 域名解析；4. 有 Redis（限流插件依赖）。

## 两个硬约束

- ⚠️ `22-higress-mcpbridge-prod.yaml` 是**整体声明式**，`apply` 会覆盖整个 `registries` 数组。
  执行前必须先 `kubectl get mcpbridge default -o yaml > backup.yaml` 备份，改完回读。
- 官方 Python 自注册 SDK 要求 **Python ≥ 3.10**，而当前 mini-mcp 跑在 3.7.17 → SDK 方案用不了；
  务实选择是本包 `11-nacos-register.sh` sidecar（只注册实例，不同步工具清单）。

## 建议顺序

先读 `02-自动化与治理-能力地图.md` 判断值不值得做 → 再按 `01-生产级全链路手册.md` 六阶段执行。
只做「开 L2 自动路由」这一步也完全合理，不需要整套落地。
