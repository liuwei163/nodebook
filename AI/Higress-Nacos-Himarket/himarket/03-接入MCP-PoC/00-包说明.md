## 这个包做什么

部署一个零依赖的最小 MCP Server（mini-mcp），让 HiChat 能调用 `get_time` / `echo` / `add`；
**PoC 形态**，生产化方案在 `04-MCP生产化/`。

## 两个必须记住的坑

① 连接点要选 **Streamable HTTP**，SSE 经带前缀的网关必断（绝对路径丢前缀）；
② `himarket-server` Pod 要能解析网关对外域名，补 hostAliases 时**先查已有数组再追加**，别覆盖掉模型域名。

## ⚠️ 本地文件名 vs 集群内文件名（重建前必读）

工作区里是 `11-mini_mcp_py2.py`（整理时加的序号前缀），但**线上集群已部署**的
ConfigMap key 与容器路径仍是 `mini_mcp_py2.py`（无前缀）。
`01-RUNBOOK-从零建MCP.md` 与 `21-mini-mcp.yaml` 已统一按**带前缀版本**书写，因此：

- **整套重建**：先按 RUNBOOK 第 5 章 `--from-file` 重建 ConfigMap，再 apply yaml —— 能跑通。
- **只 apply yaml 不重建 ConfigMap** → 容器找 `/app/11-mini_mcp_py2.py` 不存在，**启动失败**。
- **想保持线上现状**：把命令写成 `--from-file=mini_mcp_py2.py=./11-mini_mcp_py2.py`
  （左侧容器内名、右侧本地文件），并把 yaml 启动命令改回 `/app/mini_mcp_py2.py`。

一句话：`--from-file` 左侧与 yaml 启动命令**必须同名**，别混用。
