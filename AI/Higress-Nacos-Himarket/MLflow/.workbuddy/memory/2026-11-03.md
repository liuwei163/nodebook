## DeepSeek-32B 推理性能优化（昇腾 910B × 8，离线 K8s + kthena）

### 环境事实（重要，后续都基于此）
- 硬件：**昇腾 910B × 8，单节点** `kcs-aip-yanfa-shengchanyu-s-qzxs8`，非 NVIDIA GPU。CANN 9.0.0，镜像 `harbor.ai.cnpc/repo/ascend/vllm-ascend:v0.22.1rc1`
- 权重存放：hostPath `/mnt/nfs-temp/models/`（该路径是 NFS 本地挂载点），容器内 `/models`
- 配置目录：`/root/masf/kthena/dp/pd-22-deepseek32B/`（内含 dk32-pd.yaml、modelserver.yaml 及多种配比实验 pd-22-32B-p1d2/p2d4/n1/numa）
- 压测工具：`scripts/npu_bench.py`（纯标准库，含 cache_bust 打散、耗时预估、并发数>请求数告警）

### 两个核心结论（都已被实测验证）
1. **`--enforce-eager` 是 TPOT 异常的根因**：禁用昇腾 ACL Graph，导致逐算子派发 + 算子融合失效。移除后 TPOT 146.5ms → 22.6ms（6.5 倍），TTFT 340→173ms，峰值吞吐 82→214 tok/s。验证方式：5 轮重复测量 TPOT 恒为 24.3ms，零漂移零错误。
2. **PD 分离在短输入为主的负载下是负优化**：共置 TP8 对比 PD 4+4，短输入 128 并发 TTFT -41%、吞吐 +24%；长输入 8 并发 TTFT -45%、吞吐 +37%；唯一例外是长输入高并发的 TPOT（PD 24.9ms 优于共置 36.6ms，因 prefill 抢占算力），但 E2E 共置仍快 20%。

### 关键数据
- 改造后短输入容量：64 并发/1542 tok/s（SLA 内），128 并发/2759 tok/s（TTFT p99 已 1.1s）
- 改造后长输入容量：4~8 并发（prefill 瓶颈）
- KV 池：TP4 时 39.92 GiB/卡，理论支持约 80 倍并发，抢占 0 次 → KV 从不是瓶颈
- PD 的 TTFT 结构：约 200ms 固定移交 + 20ms × 并发 的 KV 串行搬运
- 同配置重复测量波动可达 23%，需 3 次取中位数
- 突发流量（32 请求/32 并发）与持续流量（256 请求/32 并发）TTFT 差 2.5 倍

### 踩过的坑
- 压测 prompt 全相同会命中 prefix cache，TTFT 严重低估 → 随机串必须加在**最前面**（prefix cache 按前缀匹配）
- `--num-requests` 必须 ≥ 并发数的 2 倍，否则实际并发被请求总数卡住
- 抢占只出现在 decode 端，prefill 不长期持有 KV
- `max_tokens` 大 + TPOT 慢时单次压测可达 1 小时，需按 `E2E = TTFT + 字数 × TPOT` 预估

## MLflow 离线部署与模型登记（2026-11-04 完成）

### 部署（形态二：SQLite + NFS）
- 镜像 harbor.ai.cnpc/ai-platform-poc/mlflow:v2.17.2，namespace ml-platform
- 关键：PV 用 NFS，mountOptions 只需 `vers=3 + nolock`（服务端是 NFSv3，加 rsize/hard 等参数反而 access denied，照抄 dolphinscheduler 的 PV 配置）
- args 最终版：`server --host 0.0.0.0 --port 5000 --backend-store-uri sqlite:////data/mlflow.db --default-artifact-root /data/artifacts`
- 不能加 --allowed-hosts（2.18+ 才有，2.17.2 会崩溃）、不能加 --serve-artifacts

### 核心认知（artifact 两种模式）
- 只要客户端走 HTTP 连 server，artifact_uri 永远是 `mlflow-artifacts:/`（代理模式），跟参数无关
- file:// 模式是"不用 server、直接操作本地文件"（set_tracking_uri("file:///path")），不是 server 的另一种配置
- 所以登记模型时 source 必须用 `mlflow-artifacts:/0/<run_id>/artifacts/<模型名>`，填 /data/... 或 file:///... 都会被拒

### 登记已有模型的流程（已跑通）
建占位 run → 在 run 的 artifact 目录建占位子目录 → 建模型条目 → 注册版本（source 用 mlflow-artifacts 前缀，真实 NFS 路径记 storage_path tag）

### 结论
- MLflow registry 是为"训练即注册"设计的，对登记已有外部模型不友好，是逆着设计用
- 等有 LoRA 训练时用 mlflow.log_model() 会顺很多
- 产出：manifests/mlflow.yaml（含登记流程注释）、scripts/register-model.sh、docs/MLflow-离线部署与模型登记.md
