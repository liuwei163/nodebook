# 两个练习脚本白话讲解（给运维人的版本）

> 你不需要会写 Python，只需要看懂"每一段在干什么、哪些行在跟 MLflow 说话"。
> 这样将来出了问题，你能分清是**训练本身的问题**还是**跟 MLflow 通信的问题**。

---

## 0. 一句话总览

| 脚本 | 角色 | 类比 |
|---|---|---|
| `05-train_real.py` | **写台账的人**：干一次活，把参数、结果、产出物全部记进 MLflow | 干完活填工单 |
| `05-load_real.py` | **读台账的人**：按模型名把模型取回来用 | 按工单号领料 |

## 一、05-train_real.py 逐段拆解（共 6 段）

### 第 1 段：导入工具 + 指定服务端地址

```python
import mlflow, mlflow.sklearn          # 加载 mlflow 客户端
TRACKING_URI = os.environ.get("MLFLOW_TRACKING_URI", "http://...svc.cluster.local:5000")
mlflow.set_tracking_uri(TRACKING_URI)  # 告诉客户端"把数据发给谁"
```

**白话**：前半段是"加载工具箱"；`set_tracking_uri` 这一行 = 给客户端配服务端地址，
**等同于** `kubectl` 读取 kubeconfig 里的 apiserver 地址。环境变量优先（你本机设的域名），
没设才用集群内默认地址——这就是为什么你不用改代码就能在本地跑。

### 第 2 段：定义两颗"旋钮"（argparse）

```python
parser.add_argument("--total-trees", type=int, default=150)
parser.add_argument("--depth", type=int, default=6)
```

**白话**：`--total-trees 200` 这种命令行参数的解析逻辑。你跑
`python 05-train_real.py --total-trees 200 --depth 4` 时改的就是这两颗旋钮。
它们不影响"记录"这件事本身，只影响训练结果——这样换参数重跑就有了可对比的数据。

### 第 3 段：选定实验 + 开一条 run

```python
mlflow.set_experiment("real-model-practice")   # 没有就自动建（= 建个文件夹）
with mlflow.start_run(run_name="iris-150x6") as run:   # 开一条新台账记录
```

**白话**：`set_experiment` = 确定往哪个文件夹放记录；
`start_run` = **翻开台账新一页**，从这行到 `with` 块结束之间记录的所有东西都归这一页。
你在 UI 里看到的每次"run"就是这么来的。

### 第 4 段：真正的训练 + 边训边记（这段是算法，不懂没关系）

```python
for step in range(1, args.steps + 1):
    model.n_estimators = per_step * step      # 这轮往森林里追加一批树
    model.fit(X_train, y_train)               # 真训练（sklearn 干活，你不用懂）
    acc = accuracy_score(y_test, model.predict(X_test))   # 打分：预测对了多少
    mlflow.log_metric("accuracy", acc, step=step)         # ← 把分数记进 MLflow
```

**白话**：训练本身是 sklearn 的事（固定套路，跟你无关）。你要认识的是最后那行
`log_metric`——**每轮训练完往台账追加一个数**，step=1~5 各记一次，
UI 上那个 accuracy 折线图就是这五行数据画出来的。
这一段出错（比如数据格式不对）→ 是"训练侧"问题；后面几段出错 → 是"MLflow 通信侧"问题。

### 第 5 段：传附件（图）

```python
plt.savefig("confusion_matrix.png", ...)
mlflow.log_artifact("confusion_matrix.png")   # ← 把这张图上传给 MLflow
```

**白话**：先在本地生成一张图（matplotlib 画图，固定套路），然后 `log_artifact`
把它**当作附件传给服务端**——类似 `curl -F file=@xxx.png` 上传文件。

### 第 6 段：存模型 + 自动登记（闭环的"写"就完成了）

```python
mlflow.sklearn.log_model(model, "model")      # ← 把模型打包存进服务端 artifact
mv = mlflow.register_model(f"runs:/{run.info.run_id}/model", "demo-iris-model")
                                              # ← 把刚存的模型登记进注册表
```

**白话**：`log_model` = 把"训练成果"打包成标准格式上传（这就是之前落容器本地盘的那批文件）；
`register_model` = **在注册表里登记一个新版本**——你在 Models 页看到的 v1、v2 就是这两行自动产生的。
到这里：参数、指标、图、模型、注册表记录，五样全进台账了。

## 二、05-load_real.py 逐段拆解（共 3 段）

### 第 1 段：按"别名"取模型（自动兜底逻辑）

```python
CANDIDATES = [
    "models:/demo-iris-model@champion",     # 新方式：查 champion 别名指向哪个版本
    "models:/demo-iris-model/Production",   # 老方式：Stage（兼容旧习惯）
]
for uri in candidates:
    try:
        model = mlflow.sklearn.load_model(uri)   # ← 核心：下载并还原模型
        break
    except Exception:
        print("不可用，试下一个")
```

**白话**：`load_model` 是 train 那边 `log_model` 的**镜像动作**——
它先问服务端"champion 别名指着哪个版本"，再把那个版本的模型文件**通过 HTTP 拉到本地、还原成可用对象**。
你日志里的 `Downloading artifacts: 5/5` 就是这一行干的（拉了 5 个文件）。
两候选都失败才报错——报错信息里会告诉你"去 UI 加别名或切 Stage"。

### 第 2、3 段：用取回的模型做预测

```python
samples = [[5.1, 3.5, 1.4, 0.2], [6.7, 3.1, 4.7, 1.5]]
preds = model.predict(samples)
```

**白话**：喂两行数据（鸢尾花的 4 个测量值），让模型判断是哪个品种，
打印结果。**能打印出结果 = 模型是"活的"**，不是死文件。

## 三、mlflow API 速查表（看懂日志排错必备）

| 代码 | 白话 | 出问题时的现象 |
|---|---|---|
| `set_tracking_uri` | 配服务端地址 | 连不上 = 地址错/网络不通/网关挂了 |
| `set_experiment` | 选文件夹（没有则建） | UI 左栏看不到实验 = 这步没执行 |
| `start_run` | 翻开新一页台账 | run 记录缺失/中断 = 训练中途崩了 |
| `log_params` | 记参数（旋钮值） | UI Params 列空白 = 没执行到这 |
| `log_metric` | 记指标（可多次=曲线） | 曲线缺失 = 训练循环里出错 |
| `log_artifact` | 传附件 | 图看不到 = 上传失败（网关/权限） |
| `log_model` | 打包存模型 | Models 页没东西 = 这里失败 |
| `register_model` | 登记进注册表 | 版本号不涨 = 这里失败 |
| `load_model` | 取回并还原 | 加载报错 = 别名/阶段没设对，或文件丢了 |
| `mlflow gc`（命令行） | 回收已删除 run 的文件 | 磁盘涨 = 该跑了 |

**排错心法**：训练报错时看输出的 `[n/6]` 序号——停在 `[3/6]` 是训练本身的问题；
停在 `[5/6]` 或 `[6/6]` 是上传/注册的问题，后者才需要你查 MLflow 服务端。

## 四、load 取回的 5 个文件到底下到哪了？

`load_model` **确实会把 5 个文件下载到你本地**，但下到的是 Windows 临时目录：

```
C:\Users\Windows\AppData\Local\Temp\tmpXXXXXXXX\     ← 每次随机生成
    ├── MLmodel           （模型说明书）
    ├── model.pkl         （模型本体）
    ├── conda.yaml / requirements.txt / python_env.yaml（环境说明）
```

**关键行为**：加载完成（模型对象还原进内存）后，这个临时目录**立刻自动删除**。
所以你在磁盘上翻不到——不是没下载，是用完即弃。

**为什么这么设计**：`load_model` 的目标是"在内存里得到一个能直接用的模型对象"，
不是"把文件保存下来"。它没有本地缓存，每次跑 `05-load_real.py` 都会重新拉一遍。

**想把 5 个文件永久保存到指定目录**（比如离线分发给没法连服务器的人）：

```powershell
# 在 mlflow-hands-on 目录下执行（会创建 downloaded-model 文件夹）
py -3.11 -c "import mlflow.artifacts; p = mlflow.artifacts.download_artifacts('models:/demo-iris-model@champion', dst_path='downloaded-model'); print('已保存到:', p)"
# 然后 dir downloaded-model 就能看到那 5 个文件
```

三种"用模型"方式的对比：

| 方式 | 文件落哪 | 用途 |
|---|---|---|
| `load_model` | 临时目录，用完即删 | 程序里直接调用预测 |
| `download_artifacts` + dst_path | 指定目录，永久保留 | 分发、备份、离线使用 |
| `mlflow models serve` | 内部临时目录 | 把模型变成 REST 接口对外服务 |
